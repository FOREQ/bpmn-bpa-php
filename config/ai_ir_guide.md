Формат IR — модель процесса в JSON (сокращённая версия docs/IR.md из FOREQ/try_yernaz).
Геометрию (координаты) НЕ указывай: раскладку строит сервис.

{
  "ir_version": "1.0",
  "process": {"id": "Task1", "name": "<название процесса>", "start": "<что запускает процесс>", "results": ["<исход 1>", "..."]},
  "lanes": [
    {"id": "Lane_A", "name": "<должность>", "kind": "role"},
    {"id": "Lane_IS", "name": "<название> (ИС)", "kind": "system"}
  ],
  "nodes": [
    {"id": "n1", "type": "startEvent", "name": "<событие-причина>", "lane": "Lane_A"},
    {"id": "n2", "type": "userTask", "name": "<Глагол + объект>", "lane": "Lane_A"},
    {"id": "n3", "type": "xor", "name": "<Вопрос?>", "lane": "Lane_A"},
    {"id": "n4", "type": "endEvent", "name": "<результат>", "lane": "Lane_A"}
  ],
  "flows": [
    {"from": "n1", "to": "n2", "label": ""},
    {"from": "n3", "to": "n4", "label": "Да"}
  ],
  "dataObjects": [
    {"id": "DO_1", "name": "<документ>", "direction": "in", "tasks": ["n2"]}
  ]
}

Типы узлов (type):
- startEvent, endEvent — начало и завершение (отдельное завершение на каждый исход);
- timer, messageCatch — промежуточные события: ожидание срока, получение сообщения;
- userTask — человек работает в информационной системе; manualTask — человек работает вне системы (бумага, лично);
- serviceTask — действие системы; sendTask / receiveTask — отправка / получение;
- task — задача без уточнения типа;
- xor — шлюз «или» (выбор одного пути; выходы подписываются условиями «Да»/«Нет» и т.п.; он же для слияния);
- and — параллельный шлюз (разветвление на одновременные ветки и обязательное слияние);
- eventGateway — событийный шлюз (ждём одно из событий).

Правила:
- дорожки — должности/роли (не организации); информационная система — отдельная дорожка «<название> (ИС)», kind=system;
- каждая задача — одно действие: «Глагол + объект» («Проверяет заявку», «Регистрирует письмо»);
- у каждого xor с двумя и более выходами — подписи условий на потоках; ветки сходятся в шлюз слияния или
  заканчиваются своим endEvent; параллельные ветки (and) обязательно сливаются шлюзом and;
- нет висящих узлов: у всех, кроме startEvent, есть вход; у всех, кроме endEvent, есть выход;
- id уникальны, латиница/цифры/подчёркивание; связи только между существующими узлами;
- документы: dataObjects, direction "in" — входящий документ (оранжевый), "out" — порождаемый (синий),
  tasks — задачи, которые с ним работают. Документы влияют на расчёт сложности — указывай все документы из текста;
- не добавляй шагов, которых нет в тексте.
